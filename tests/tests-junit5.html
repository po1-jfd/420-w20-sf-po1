Tests automatisés - JUnit 5 ​

Les tests automatisés vérifient le fonctionnement du code sans intervention manuelle. Ils protègent contre les régressions, servent de documentation et renforcent la confiance dans le code.

Objectifs d'apprentissage ​

Après cette section, tu seras capable de...

  • Écrire un test unitaire avec JUnit 5
  • Structurer un test selon le patron Arrange-Act-Assert (AAA)
  • Nommer les méthodes de test selon la convention BDD
  • Identifier les cas critiques et les cas limites à tester
  • Utiliser les assertions JUnit principales

Pourquoi les tests automatisés ? ​

  • Confiance : le code a le comportement attendu
  • Régression : une modification ne brise pas un comportement existant
  • Documentation : les tests décrivent les comportements du système
  • Débogage : les tests isolent la source d'un problème

Configuration dans Maven ​

Ajoute la dépendance JUnit 5 dans pom.xml :

xml
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>5.10.0</version>
    <scope>test</scope>
</dependency>

Structure d'un test - Arrange-Act-Assert (AAA) ​

java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class CalculatriceTest {

    @Test
    void etantDonneDeuxNombres_lorsquOnAdditionne_alorsRetourneLaSomme() {
        // ARRANGE - préparer les données
        int a = 5;
        int b = 3;
        Calculatrice calculatrice = new Calculatrice();

        // ACT - exécuter l'action testée
        int resultat = calculatrice.additionner(a, b);

        // ASSERT - vérifier le résultat
        assertEquals(8, resultat);
    }
}

Nomenclature BDD ​

La convention Behaviour Driven Development nomme les tests selon le scénario :

etantDonne[Contexte]_lorsque[Action]_alors[ResultatAttendu]
java
// Exemples de noms de méthodes de test
void etantDonneSoldePositif_lorsquOnRetire_alorsLeSoldeEstReduit()
void etantDonneSoldeInsuffisant_lorsquOnRetire_alorsLanceException()
void etantDonneListeVide_lorsquOnDemandeLaSize_alorsRetourneZero()

Les noms de test sont de la documentation

Un bon nom de test décrit un comportement précis. Quelqu'un qui lit les noms de tes tests doit comprendre ce que fait la classe testée, sans lire son code.

Assertions JUnit 5 ​

AssertionUsage
assertEquals(expected, actual)Valeurs égales
assertNotEquals(unexpected, actual)Valeurs différentes
assertTrue(condition)Condition vraie
assertFalse(condition)Condition fausse
assertArrayEquals(expected, actual)Tableaux identiques
assertIterableEquals(expected, actual)Collections identiques
assertThrows(ExceptionType.class, () -> ...)Exception lancée
assertNull(value)Valeur null (utiliser avec parcimonie)
java
// Exemple d'utilisation des assertions
assertEquals("Alice", etudiant.getPrenom());
assertTrue(compte.estActif());
assertThrows(IllegalArgumentException.class, () -> {
    new Etudiant(null, "Tremblay", 20);
});

Évite les valeurs codées en dur dans les assertions

Utilise des assertions relatives plutôt que des valeurs calculées à la main :

java
// Mauvais : valeur calculée à la main
assertEquals(8.5, calculerMoyenne(new double[]{7, 10}));

// Bon : assertion relative à ce qu'on a arrangé
double[] notes = {7, 10};
double moyenne = calculerMoyenne(notes);
assertEquals((7.0 + 10.0) / 2, moyenne, 0.001);

Cas critiques et cas limites ​

Un bon test unitaire ne teste pas que le cas "normal". Identifie aussi :

  • Cas normal : entrée typique valide
  • Cas limite : valeurs aux frontières (0, négatif, valeur maximale, liste vide)
  • Cas d'erreur : entrée invalide (null, hors plage) - attendez une exception
java
// Cas normal
void etantDonneNoteValide_lorsquOnLaPasse_alorsReussit()

// Cas limite
void etantDonneNoteEgaleA60_lorsquOnLaPasse_alorsEchec()  // seuil de passage
void etantDonneNoteEgaleA59_lorsquOnLaPasse_alorsReussit() // limite inférieure

// Cas d'erreur
void etantDonneNoteNegative_lorsquOnLaPasse_alorsLanceException()

Organisation des fichiers de test ​

Les tests doivent être dans un package miroir : même nom de package que la classe testée, mais sous src/test/java/.

src/
├── main/java/ca/csfoy/w20/banque/
│   └── CompteBancaire.java
└── test/java/ca/csfoy/w20/banque/
    └── CompteBancaireTest.java     ← même package
Exemple complet - test d'une classe Panier
java
package ca.csfoy.w20.boutique;

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class PanierTest {

    @Test
    void etantDonnePanierVide_lorsquOnDemandeLaTaille_alorsRetourneZero() {
        Panier panier = new Panier();
        assertEquals(0, panier.getNombreArticles());
    }

    @Test
    void etantDonneArticleValide_lorsquOnLAjoute_alorsLaTailleEstUnite() {
        Panier panier = new Panier();
        panier.ajouterArticle("Clavier", 49.99);
        assertEquals(1, panier.getNombreArticles());
    }

    @Test
    void etantDonneArticleAvecPrixNegatif_lorsquOnLAjoute_alorsLanceException() {
        Panier panier = new Panier();
        assertThrows(IllegalArgumentException.class, () -> {
            panier.ajouterArticle("Clavier", -10.0);
        });
    }

    @Test
    void etantDonneDeuxArticles_lorsquOnCalculeLeTotal_alorsRetourneLaSomme() {
        Panier panier = new Panier();
        panier.ajouterArticle("Clavier", 49.99);
        panier.ajouterArticle("Souris", 29.99);
        assertEquals(49.99 + 29.99, panier.getTotal(), 0.001);
    }
}
