Créateur, Contrôleur, Acteur ​

Ces trois rôles GRASP définissent qui doit créer des objets, qui doit orchestrer les traitements, et qui doit exécuter le travail.

Objectifs d'apprentissage ​

Après cette section, tu seras capable de...

  • Distinguer les rôles de contrôleur, d'acteur et de créateur
  • Attribuer chaque rôle à la classe appropriée dans un système
  • Expliquer pourquoi la séparation de ces rôles améliore la maintenabilité

Après cette section, tu seras capable de...

  • Différencier les rôles de contrôleur, d'acteur et de créateur
  • Attribuer chaque rôle à la classe appropriée dans un système
  • Expliquer pourquoi la séparation de ces rôles améliore la maintenabilité

Le Créateur ​

Principe : qui doit créer une instance de la classe A ?

La classe B devrait créer les instances de A si B :

  • Contient des instances de A (composition ou agrégation)
  • Possède les données nécessaires pour initialiser A
  • Est intimement liée à A dans le domaine
java
// Commande crée ses lignes - Commande est le créateur de LigneCommande
public class Commande {
    private ArrayList<LigneCommande> lignes;

    public void ajouterProduit(Produit produit, int quantite) {
        // Commande crée la LigneCommande car elle la contient
        LigneCommande ligne = new LigneCommande(produit, quantite);
        this.lignes.add(ligne);
    }
}

Indication du créateur

Si pour créer un objet A tu as besoin des données d'un objet B, B est probablement le bon créateur de A.

L'Acteur ​

Principe : l'acteur est la classe qui possède l'information et effectue le vrai travail. C'est l'expert en information à qui on délègue.

java
// Siège est un acteur : il connaît son état et le change lui-même
public class Siege {
    private SiegeStatut statut;

    public void reserver() {
        if (this.statut != SiegeStatut.DISPONIBLE) {
            throw new IllegalStateException("Ce siège n'est pas disponible.");
        }
        this.statut = SiegeStatut.RESERVE;
    }

    public boolean estDisponible() {
        return this.statut == SiegeStatut.DISPONIBLE;
    }
}

L'acteur ne demande pas à d'autres classes des informations sur lui-même - il répond lui-même aux questions le concernant.

Le Contrôleur ​

Principe : le contrôleur orchestre les traitements sans les exécuter lui-même. Il délègue aux acteurs et coordonne le flux.

java
// Avion est un contrôleur : il orchestre la réservation
public class Avion {
    private ArrayList<Siege> sieges;

    public void reserverSiege(String numeroSiege, String nomPassager) {
        Siege siege = this.trouverSiege(numeroSiege);

        // Délègue à l'acteur (le siège lui-même)
        siege.reserver();

        // Crée la réservation (rôle de créateur)
        Reservation reservation = new Reservation(siege, nomPassager);
        this.reservations.add(reservation);
    }

    private Siege trouverSiege(String numero) {
        for (Siege s : this.sieges) {
            if (s.getNumero().equals(numero)) return s;
        }
        throw new IllegalArgumentException("Siège introuvable : " + numero);
    }
}

Le contrôleur ne fait pas le travail

Un contrôleur typique :

  • Récupère les objets concernés
  • Valide les préconditions globales
  • Délègue les opérations aux acteurs
  • Coordonne le résultat

Si le contrôleur contient beaucoup de logique métier, c'est un signe que certaines responsabilités appartiennent aux acteurs.

Les trois rôles en interaction ​

Scénario : réserver un siège dans un avion

Contrôleur : Avion
  → trouve le siège (logique de recherche)
  → délègue la réservation au siège (acteur)
  → crée une Réservation (créateur)

Acteur : Siege
  → valide son propre état (estDisponible ?)
  → change son statut

Créateur : Avion
  → crée la Réservation avec les données disponibles
Exemple complet - Rôles dans un système de réservation
java
public enum SiegeStatut { DISPONIBLE, RESERVE, OCCUPE }

public class Siege {
    private String numero;
    private SiegeStatut statut;

    public Siege(String numero) {
        this.numero = numero;
        this.statut = SiegeStatut.DISPONIBLE;
    }

    // ACTEUR : connaît son propre état
    public boolean estDisponible() {
        return this.statut == SiegeStatut.DISPONIBLE;
    }

    // ACTEUR : gère sa propre transition d'état
    public void reserver() {
        if (!this.estDisponible()) {
            throw new IllegalStateException("Siège " + this.numero + " non disponible.");
        }
        this.statut = SiegeStatut.RESERVE;
    }

    public String getNumero() { return this.numero; }
}

public class Avion {
    private String immatriculation;
    private ArrayList<Siege> sieges;
    private ArrayList<Reservation> reservations;

    public Avion(String immatriculation, int nombreSieges) {
        this.immatriculation = immatriculation;
        this.sieges = new ArrayList<>();
        this.reservations = new ArrayList<>();
        for (int i = 1; i <= nombreSieges; i++) {
            this.sieges.add(new Siege(String.valueOf(i)));
        }
    }

    // CONTRÔLEUR : orchestre la réservation
    public Reservation reserverSiege(String numero, String nomPassager) {
        Siege siege = this.trouverSiege(numero);
        siege.reserver();                              // délègue à l'acteur
        Reservation res = new Reservation(siege, nomPassager);  // créateur
        this.reservations.add(res);
        return res;
    }

    private Siege trouverSiege(String numero) {
        for (Siege s : this.sieges) {
            if (s.getNumero().equals(numero)) return s;
        }
        throw new IllegalArgumentException("Siège introuvable : " + numero);
    }
}
